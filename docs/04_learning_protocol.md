# 每日学习与面试协议

## 每日协作流程

1. 开始前：明确当天业务增量、原理目标和验收标准。
2. 原理先行：只讲马上会用到的核心机制和数据流。
3. 共同实现：我负责拆解、提示、代码审查和排障，你需要亲自解释关键代码。
4. 自动验证：运行测试、查看 API/数据库/Trace 证据。
5. 原理整理：在提问前，按“请求进入 → 状态变化 → 依赖调用 → 失败处理 → 返回/持久化”的操作流程总结当天知识。
6. 面试验收：我切换成面试官，先问主问题，再根据回答追问薄弱点。
7. 错题闭环：记录“错误答案、正确原理、如何验证、隔天复问”。

## 提问规则

- 每天通常 6–12 个主问题，全部问题控制在 30 个以内；若基础原理仍不满足当天要求，再按学习规则继续追问。
- 原理、底层框架、边界和故障路径占大多数；代码只问最关键的数据流和并发/资源问题。
- 不接受只背定义。每个核心概念至少能回答：它解决什么问题、系统中放在哪里、失败会怎样、替代方案是什么。
- 代码出现后立即解释其输入、输出、状态变化和错误路径。
- 我不会用一个虚假的数学模型宣称掌握率。这里的“98% 把握”按可观察标准执行：连续两轮能独立解释、能迁移到新场景、能纠正反例、能读懂对应代码，且关键题无概念性错误。

## 学习责任边界

我会写出脚手架、测试和示范，但不会把“项目在你的电脑上跑起来”等同于“你掌握了”。你需要在每日面试中独立解释，关键模块还要完成小范围改造或故障排查。这样最终仓库才既是作品，也是你能守住的面试经历。
