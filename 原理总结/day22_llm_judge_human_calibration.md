# Day22：LLM Judge 与人工校准

## 业务问题

确定性规则能检查 Tool、参数、Policy 和状态，却难以完整枚举解释是否清楚、证据理由是否充分。LLM Judge 可以评价软语义，但会波动和偏置，不能用一次总分代替真相。

## 完整主流程

Day21 硬门禁 → 版本化四维 Rubric → A/B 隐藏版本身份 → 两名人工独立标注并保留分歧 → Judge 通过 ModelGateway 结构化判分 → 每个 Case 交换 A/B 再判一次 → 还原版本身份 → 计算人工一致率、Judge/人工一致率、顺序敏感和分数误差 → 校准达标后启用语义门禁 → `硬门禁 AND 语义门禁` 决定发布。

## 四个语义维度

1. 清晰度：结论和原因是否一次可懂。
2. 证据解释：是否把已给事实连接到结论，不编造。
3. 推理完整性：是否覆盖关键冲突、不确定性和处置理由。
4. 可执行性：是否给出具体下一步和停止/审核条件。

Judge 不评价 Tool 名称/参数、订单绑定、授权、审批、Policy、最终状态和失败域，这些继续由 Day21 硬规则负责。

## 状态与异常

Judge 输出只能包含四维 1–4 分、A/B/tie、置信度和受控理由码。字段越界、额外字段、偏好与分数冲突都会被 ModelGateway 拒绝。交换前后版本偏好不同的 Case 标为 `unstable`，不隐藏成一个平均偏好。

## 人机协同

两名人工标注者独立工作，分歧后裁决；Judge 不接收人工标签。人工也可能不一致，所以原始分歧必须进入报告，人工标签不是未经审计的绝对真理。

## 核心结果

8 个合成 Case 中：人工偏好一致率 87.5%，Judge/人工一致率 87.5%，顺序一致率 87.5%，顺序敏感率 12.5%，分数 ±1 命中率 100%。Candidate 四维平均分 3.4375，Baseline 为 2.25，合成对照提升 1.1875 分。一个 Judge 语义满分但硬门禁失败的 Case 仍被拒绝，证明 Judge 没有安全放行权。

## 与前后 Day

Day20 提供评估基础，Day21 提供硬门禁，Day22 增加经人工校准的软语义判断，Day23 将把分歧和失败样本接入反馈闭环与版本实验。

## 证据边界

当前使用合成标签和确定性 Judge fixture，只证明工程流程，不代表生产 Judge 准确率。上线前必须用脱敏真实样本、真实独立标注者和目标模型重新校准。
